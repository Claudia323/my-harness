# 허들링 앱 — 유저스토리 (MVP 1차)

출처: [docs/prd.md](docs/prd.md). 구매자 스토리(3-5)는 Phase 2라서 제외했습니다.

## 유저스토리

| # | 유저스토리 | PRD 근거 |
|---|---|---|
| 1 | **무료 학습자**가 공개 학습자료를 카테고리별로 둘러보고 유료 자료를 미리본다. | 3-1, 6-1 |
| 2 | **유료 멤버**가 강의자료·템플릿·프롬프트·스킬 카드를 한곳에서 찾아 열람하고 다운로드한다. | 3-2, 6-2, 6-3 |
| 3 | **유료 멤버**가 월간 미션 산출물을 제출하고, 제출 완료된 제출물을 내 자산으로 전환한다. | 3-3, 6-4 |
| 4 | **판매 승인 회원**이 내 자산을 판매 신청하고 검수 상태를 확인한다. | 3-4, 6-5, 7-4 |
| 5 | **운영자**가 판매 신청 자산을 필수 체크리스트로 검수해 승인하거나, 수정을 요청하거나, 반려한다. | 3-6, 6-7 |

## 어기면 안 되는 것

| # | 규칙 | PRD 근거 |
|---|---|---|
| A | 판매 자산은 운영자 검수를 통과해야 한다. 판매 신청은 판매 승인 회원(`seller`)만 할 수 있다. | 14, 9 결정 2 |
| B | 개인정보, 고객정보, 회사기밀, 타인의 저작물은 판매 자산에 포함될 수 없다. | 14, 6-7 기준 6·7 |

## 미결 사항

1. 판매 가격을 누가 정하는지 PRD에 정해져 있지 않다. 3-4에는 판매자가 가격을 확인한다고 되어 있고, 6-7에는 운영자가 "가격 설정 또는 가격 승인"을 한다고 되어 있다.
2. 비회원과 무료 회원을 스토리 1에 함께 묶었다. 권한은 7-1과 7-2로 나뉘어 있다.
3. 미션 피드백은 MVP에서 제외되어(9 결정 4) 스토리 2에서 뺐다.

# 작업 방식 — 실제로 어떻게 했는지 (AI 없이 손으로 한 마지막 경험)

위 유저스토리("무엇을 위한 일인지")와는 별개입니다. 출처는 PRD가 아니라 작업자 본인의 진술입니다.

| # | 문장 | 명사 (산출물) | 멈칫 (게이트) | 넘김 (에이전트 경계) |
|---|---|---|---|---|
| 1 | 나는 uibowl에서 경쟁사 레퍼런스를 수집한다. | 경쟁사 레퍼런스 모음 | 기획자의 컨펌이 필요함 | 없음 |
| 2 | 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다. | 레퍼런스 분석 / 반영 포인트 | 없음 | 없음 |
| | **G1** 레퍼런스 분석 → 화면설계 | | 필수 | |
| 3 | 분석 내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다. | 화면 설계 문서 | 없음 | 없음 |
| | **G2** 화면설계 → 디자인 제작 | | 필수 | |
| 4 | Figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다. | UI 키스크린 2~3개 | 없음 | 없음 |
| 5 | 내부 관계자들과 협의 후 컨셉 시안을 확정한다. | 확정 컨셉 시안 | 없음 | 없음 |
| 6 | 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다. | 디자인 토큰, 컴포넌트, 화면 디자인 | 없음 | 없음 |

## 미결 사항

1. G2 위치: 3↔4 사이로 두었음. "디자인 제작"이 6번(토큰·컴포넌트)을 뜻하면 5↔6 사이로 이동.
2. 1번의 기획자 컨펌이 G1과 같은 게이트인지, 1↔2 사이 별도 게이트(G0)인지 미확정.
