# 파이프라인

입력: 사용자 플로우 1개 (purpose.md 참조)

| 단계 | 원본 문장(story-work) | 입력 | 출력 |
|---|---|---|---|
| S1 리서치 | 1, 2 | 플로우명, prd.md, story-service.md | 레퍼런스 5~10개(uibowl 링크) + 레퍼런스별 반영 포인트 ≥1줄 |
| G1 | 1의 기획자 컨펌 → 기계 판정 + 기획자 참고 공유로 대체 (R5) | | |
| S2 화면설계 | 3 | S1 출력, prd.md, story-service.md | 화면 2~3개별 목적·구성 요소·상태 |
| G2 | | | |
| S3 키스크린 | 4, 5 | S2 출력, design.md | Figma 390×844 프레임 2~3개 (기획자 확정) |
| S4 토큰·컴포넌트 | 6 | S3 확정 프레임, design.md | Figma 변수·컴포넌트 세트 + 적용 화면 |

story-work 7(가이드 위반 검토)은 단계가 아니라 판정 스크립트가 담당.

## 되돌아가기

| 실패 지점 | 복귀 |
|---|---|
| G1 실패 (레퍼런스 부족 / 기획자 반려) | S1 |
| G2 실패 (설계 누락 / 규칙 A·B 위반 흐름) | S2 |
| S3 판정 실패 (design.md 위반) | S3 |
| S3 기획자 반려 | S2 |
| S4 판정 실패 | S4 |

같은 단계 복귀는 최대 3회. 초과 시 중단하고 사람에게 보고.
